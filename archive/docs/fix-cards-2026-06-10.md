## 定位
`modules/script-editor/src/components/WriteTab.jsx`,四個錨點:
1. Forward sync effect — 錨點註解 `// Forward sync — push parsedBlocks 到 parent blocks`(約 L265)
2. Reverse sync effect — 錨點註解 `// Reverse sync — blocks 從外部變動時，重產 textarea`(約 L295)
3. 草稿自動儲存 effect — 錨點註解 `/* debounced auto-save */`(約 L455,500ms debounce 呼叫 `saveDraft(content, workId, writeMode)`)
4. `const switchWriteMode = React.useCallback((nextMode) => {`(約 L533)

相關既有機制(讀懂再動手):
- `syncTokenRef`:forward push 自己造成的 blocks 變動,reverse effect 收到後遞減略過(echo guard)
- `lastReverseRef`:reverse 設進來的 content,forward effect 比對後略過(不回推)
- `initializedRef`:首次 mount 時若 blocks 非空,跳過第一次 forward push(避免 draft 吞掉 server data);blocks 為空時立即同步(新建作品 SEED 寫入)
- `forwardTimer` 350ms / `saveTimer` 500ms 兩個 debounce

## 現在的行為
重現一(模式切換丟字):dev server 開 Script Editor → Write(Script 模式)→ textarea 末尾打一行新台詞 → 1 秒內點 Novel → 點回 Script → **該行從 textarea、localStorage 草稿 `sw_write_draft_v1_{workId}`、blocks 三處消失**,狀態列還顯示「⇄ Synced」。
重現二(TAB 切換丟字):同樣打一行 → 立即切「編輯 Editor」TAB → 切回「速寫 Write」→ 該行消失(WriteTab 因 `key={tab + currentWork}` 整個 remount)。

機制:
- 兩個 debounce 在 unmount / 模式切換時被 `clearTimeout` 直接丟棄,最後 ≤350/500ms 的輸入既沒存草稿也沒進 blocks;
- reverse sync effect 依賴陣列含 `isScriptMode, workId, writeMode`,切回 script 時 effect 重跑,**blocks 根本沒變**也會用舊 blocks 的 `blocksToPlainScript()` 結果覆寫 content 並 `saveDraft()` 回存,把 `switchWriteMode` 剛載入的較新草稿蓋掉。

## 預期的行為
審查報告發現 #1 修復需求原文:
> 1. Reverse sync(blocks → textarea 重生成)只准在 blocks 內容真正變動時執行:用 ref 記住上次處理過的 blocks,effect 因 writeMode / workId / characters / mount 觸發但 blocks 沒變時,不准重生成、不准 saveDraft。
> 2. 離開 Script 模式(switchWriteMode)與 WriteTab unmount 前必須 flush:未到期的 500ms 草稿儲存立即執行;未到期的 350ms forward sync 立即 push 進 blocks。禁止只 clearTimeout 丟棄。

行為不變式(全部要成立):
- I1 打字後不論多快切換(模式或 TAB),輸入不遺失。
- I2 首次 mount 時「Editor/外部改動流回 Write」的既有行為保留(blocks 與草稿不同時,以 blocks 重生成 — `lastBlocksRef` 初始 null,第一輪照常執行)。
- I3 新建 custom work 的 SEED 首次同步(blocks 為空時立即 push)不能壞。
- I4 Novel / Notes 模式打的字在快速 TAB 切換下也不遺失(unmount flush 必須對當前 mode 的 draft key 生效)。
- I5 不形成同步迴圈(既有 syncTokenRef / lastReverseRef 守衛邏輯保留語意)。

## 修法方向
1. **Reverse sync gating**:新增 `lastBlocksRef = useRef(null)`。effect 內(在 `!isScriptMode` early-return 之後、echo-token 檢查之後):`if (blocks === lastBlocksRef.current) return;` 處理完(不論有沒有 regenerate)記 `lastBlocksRef.current = blocks`。注意:在 novel/notes early-return 時**不要**更新 lastBlocksRef(否則切回來時誤判已處理)。
2. **switchWriteMode flush**:在現有 `saveDraft(content, workId, writeMode)`(這行已存在,保留)之前/之後補 forward flush — 若目前是 script 模式且 `setBlocks` 存在且 `content !== lastReverseRef.current`:`clearTimeout(forwardTimer.current)` 後**同步**執行 `syncTokenRef.current++; setBlocks(diffMergeBlocks(blocks, parsePlainScript(content, characters)))`(WriteTab 已 import 這兩個函式;若 useCallback 依賴不足就補依賴或改用 ref 取最新值)。
3. **Unmount flush**:新增一個 deps 為 `[]` 的 effect,cleanup 內做 flush。用 refs(`contentRef` / `writeModeRef` / `workIdRef` / `blocksRef` / `charactersRef`,每次 render 同步更新)取最新值:(a) 對當前 mode 執行 `saveDraft(contentRef.current, workIdRef.current, writeModeRef.current)`;(b) 若當前是 script 模式且 content 不是 reverse 推進來的,push `diffMergeBlocks(blocksRef.current, parsePlainScript(contentRef.current, charactersRef.current))` 進 setBlocks。
4. **已知陷阱**:
   - flush 的 `syncTokenRef.current++` 與切換後 reverse effect 在 novel 模式 early-return 的互動:token 可能殘留 1,切回 script 第一輪 reverse 會被它吃掉一次 — 確認這不會讓「外部 blocks 真變動」被漏掉(必要時 early-return 前先消化 token,或 flush 改為不加 token 而靠 lastBlocksRef 判斷)。自行推演 + 用驗收測試證明。
   - `activeChapter` 章節檢視模式下,flush 用的必須是完整 `content`(不是 chapterView 的切片)— 現有 saveDraft 用 content 已正確,照搬。
   - React 18 批次更新:switchWriteMode 內的 setBlocks 與 setWriteMode 同批 — effect 只跑一次,推演順序時以此為準。
5. **邊界(不准動)**:parser.js、BgmPanel、useVoiceTTS、App.jsx、props 介面(`{ blocks, setBlocks, characters, workId }`)、localStorage key 命名、SEED 內容、任何 UI/樣式。

## CARD-06(草案)[S1?] choice block round-trip 結構遺失
發現於本次寫卡查證(超出審查報告範圍,依協議 A7-6 不混入正式批次):
`blocksToPlainScript` 把 choice block 輸出為 `#choice：選項1 / 選項2`,但 `parsePlainScript` 的 COMMAND_RE 會把它 parse 回 **command** block(type 變了,`options[].nextBlockId` 結構消失)。後果:在 Editor 建立的選項分支,只要在 Write 模式碰過文字,結構就被打平。黑星專案的 choice button 待修項可能與此相關。修法候選:parsePlainScript 特判 `#choice：`(比照 `#scene：`)。**未授權前不動。**
