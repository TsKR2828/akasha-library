# FIX-CARD CARD-A 〔#1 返回鍵套娃〕
- 嚴重度:S2（人因/體驗）　類型:移除　區域:**活躍（Script Editor）**　風險:無
- 檔案白名單:`modules/script-editor/src/App.jsx`（僅此一檔）

## 定位（錨點）
1. 返回按鈕:`title="返回阿卡夏"`（約 App.jsx:621-627，在 `SwHeader` 內）
2. 傳入處:`onBack={goBack}`（約 App.jsx:4651）
3. 函式:`const goBack = () => { window.location.href = "../../index.html"; };`（約 App.jsx:4489）
4. `SwHeader` 的參數列:`function SwHeader({ tab, setTab, onBack, onAI, workSwitcher })`（約 App.jsx:600）

## 現在的行為
點 Script Editor 左上返回鍵 → `goBack` 把 **iframe 自己的** `window.location` 設成 `../../index.html`。因 Script Editor 跑在 App Shell 的 `#module-frame` iframe 內，等於把整個圖書館載進自己的框 → 畫面變「圖書館裡又一個圖書館」（套娃）。

## 預期的行為 / 改法
完全移除返回鍵（左側側欄已提供導航且關不掉，返回鍵多餘）：
1. 刪 `SwHeader` 內 `title="返回阿卡夏"` 那顆 `<button>`（含其 `SwIcon name="back"`）。
2. 從 `SwHeader` 參數移除 `onBack`，並刪傳入處 `onBack={goBack}`。
3. 刪除已無人呼叫的 `goBack`。
- **邊界:不准動分頁切換（tab/setTab）、不准動 `workSwitcher`、不准動 `onAI` 與其餘 header 元素。**

## 驗收（不需讀碼）
打開 Script Editor → 左上不再有返回箭頭 → 用左側側欄切到別的模組再切回 → 正常顯示，不再出現套娃。

# FIX-CARD CARD-B 〔#4 作品刪除藏起來〕
- 嚴重度:S2　類型:做明顯　區域:**活躍**　風險:低
- 檔案白名單:`modules/script-editor/src/App.jsx`（僅此一檔）

## 定位（錨點）
1. `function WorkSwitcher({ currentId, onSwitch, workIndex, onNewWork, onDeleteWork })`（約 App.jsx:4424）
2. 刪除鈕的條件渲染:`.find(w => w.id === currentId)?._custom && (` 後接 `title="刪除此自訂作品"` 的 `<button>×`（約 App.jsx:4446-4453）
3. 刪除邏輯（**只讀勿改**）:`const deleteCurrentWork = () => {`（約 App.jsx:4618-4633，含 `window.confirm` 與 10 個 per-work key 清除）

## 現在的行為
刪除「×」鈕**只在當前作品是「自訂作品」（`_custom`）時才渲染**；內建作品（羅恩格林、黑星劇場）完全不顯示刪除鈕。實測:只有 2 個內建作品時，畫面上 **0 顆刪除鈕**。就算切到自訂作品，×也是 26px 透明細框、緊鄰較大的「＋」，極易整個漏看 → 使用者結論「沒有刪除功能」。

## 預期的行為 / 改法
1. 自訂作品時把刪除鈕做明顯:改成帶文字「🗑 刪除」或 hover 放大 + 提高邊框/底色對比。
2. （建議）內建作品時顯示一個 disabled、灰階、`title="內建作品不可刪除"` 的占位鈕，讓使用者知道「刪除是存在的，只是這個作品不能刪」，而非「找不到」。
- **邊界:不准改 `deleteCurrentWork` 的清 key 邏輯（10 個 per-work key 已驗對稱）；不准讓內建作品可刪；不准改 `WorkSwitcher` 的下拉選單與新增鈕行為。**

## 驗收（不需讀碼）
新增一個自訂作品 → 旁邊出現一眼可見的刪除鈕 → 點它跳「確定刪除…」確認框 → 確認後該作品消失、自動切回別的作品；切到內建作品時，看得出「這個不能刪」而不是空無一物。

# FIX-CARD CARD-C 〔#3 角色 / Persona Slot 編輯刪除藏起來〕
- 嚴重度:S2　類型:做明顯　區域:**活躍**　風險:低
- 檔案白名單:`modules/script-editor/src/App.jsx`、`modules/script-editor/src/components/WriteTab.jsx`

## 定位（錨點）
1. Persona Slots 容器與徽章:`WriteTab.jsx` 內 `Persona Slots`（標題）、`function SlotBadge(`（約 L968）、`onClick={(e) => onSlotContext(e, n)}` / `onContextMenu={(e) => onSlotContext(e, n)}`（約 L760-762）
2. Slot 選單（**功能已在，只讀**）:`{/* ───── slot context menu ───── */}`（約 WriteTab.jsx:776-821，含 `✕ 清除` 與指派項）
3. 角色表編輯/刪除鈕:`App.jsx` 角色區 `<SectionLabel latin="Personae" zh="角色" />` 下方，`{ch && <button ... title="編輯角色"` 與 `{ch && <button ... title="刪除角色"`（約 App.jsx:2923-2926）

## 現在的行為
- **Persona Slots**:點 Alt+1~9 任一 slot **會跳選單**（實測:▸插入／🔒鎖定／**✕清除**／指派 #scene·旁白·角色·自訂）——「清除」＝刪除、「指派」＝改，功能都在；但「要點一下才知道有選單」對非技術使用者不直覺。
- **角色表**:編輯（✎）/刪除（×）鈕**只在先點選某個角色後**才出現（`{ch && …}`），且只有 22px，使用者只看到永遠在的「＋新增」→ 結論「只能新增、不能編輯刪除」。

## 預期的行為 / 改法
1. Persona Slots:在「Persona Slots」標題旁加一行小字提示「點擊可指派／編輯，選單內可✕清除」；或讓**已有內容的 slot** 顯示一個小「⋯」記號示意可操作。
2. 角色列:把 ✎編輯 / ×刪除 改成「**滑過角色列即顯示**」（不必先點選），或在每列尾端常駐淡色小 ✎/×。
- **邊界:不准改角色資料結構、不准改 slot 的 lock/unlock/assign 邏輯、不准改 `handleCharDelete` 與角色 Modal 行為。只做「讓入口看得到」。**

## 驗收（不需讀碼）
Write 分頁點任一 Persona Slot → 一眼看到「清除/改指派」；Editor 分頁滑過任一角色列 → 直接看到編輯與刪除圖示，不必先點選該角色。

# FIX-CARD CARD-F 〔#2b 全域日間模式〕　🆕 新功能 · ⚠️ 全站含凍結 · 需先確認凍結窗
- 嚴重度:功能新增　類型:跨全站功能　區域:**App Shell + 全部模組（含凍結）**　風險:中高
- 檔案白名單（分步逐模組）:`index.html`（App Shell）+ 各模組 `index.html` / React 入口 + `assets/styles/shared.css`

## 定位（錨點）
1. 切換邏輯:`function toggleMode()`（約 index.html:2575）
2. 切換鈕（目前在 footer）:`id="mode-toggle"`（約 index.html:1537）、`id="mode-icon"`
3. 模組載入處:`function openModule(`（index.html）
4. 持久化:`localStorage.setItem('akasha-mode', next)`、`document.documentElement.setAttribute('data-mode', savedMode)`

## 現在的行為
明暗切換鈕藏在左下角 footer；`toggleMode()` **只**設 App Shell 自己的 `<html data-mode>` + 存 `localStorage['akasha-mode']`，**完全沒有 postMessage 給 iframe**。結果:切日間只有外框（側欄/頂列/總覽）變色，**iframe 內的各模組維持深色不變**。

## 預期的行為 / 改法（分步，建議先做樣板再推廣）
1. 把切換鈕挪到/複製到**頂部共用列**（`#btn-summon` 旁），footer 那顆可保留或移除。
2. `toggleMode` 設 mode 後，**postMessage `{ type:'akasha-theme', mode }` 給 `#module-frame`**；且 `openModule` 在 iframe 載入完成時補送一次當前 mode（確保切模組後新模組也正確）。
3. 每個模組加監聽:收到 `akasha-theme` → 在自己的 `<html>` 設 `data-mode`，並補一套 `[data-mode="light"]` 的亮色 CSS 變數（含 React 兩模組 Script Editor / 試算表的入口）。
4. **先只做 1 個模組（建議 Code & Data）當亮色樣板，給月月確認配色，通過後再推廣其餘模組。**
- **邊界:深色仍為預設；亮色只動 CSS 變數層（符合 README「CSS 變數集中管理」原則）；不准改任何模組的功能邏輯。**

## 驗收（不需讀碼）
頂部切到日間 → 外框與**當前開啟的模組一起**變亮色；切換到其他模組，新模組也是亮色；重整頁面後維持所選模式。
